# Nojima Tool Hub

店舗スタッフ向け資料・Webツールをまとめるサイトです。URL登録情報はFirebase Realtime Databaseへ保存され、同じFirebaseプロジェクトを使う端末間で共有されます。

## GitHubへ資料をアップロードする方法

GitHubの操作に慣れていない方向けの手順です。資料ファイルをリポジトリへ追加すると、サイトがファイルを自動で一覧に表示します。`readme.md`は案内文書として扱われ、一覧には表示されません。

### 1. リポジトリを開く

ブラウザで[Nojima Tool HubのGitHubリポジトリ](https://github.com/nojitool/noji_tool_2.0)を開き、GitHubにサインインします。リポジトリ内のファイル・フォルダ一覧が表示されます。

### 2. 資料の分類フォルダを選ぶ

現在公開中のリポジトリでは、4つの分類フォルダはリポジトリの直下にあります。アップロードする資料の分類に合うフォルダを開いてください。

| サイト上の分類 | 開くフォルダ |
| -------------- | ------------ |
| 家電           | `家電/`      |
| 季節AV         | `季節AV/`    |
| 情報           | `情報/`      |
| 通信           | `通信/`      |

**新たに`files/`フォルダを作る必要はありません。** 既存フォルダの中へ入れてください。サイトはこの現在の配置に加え、`files/家電/`のような`files/`内の配置も検出します。

### 3. 「Upload files」を選ぶ

分類フォルダを開いた状態で、ファイル一覧の上にある **Add file** を押し、メニューから **Upload files** を選びます。次の画面で、パソコンから資料を選ぶか、資料をアップロード欄へドラッグ＆ドロップします。複数のファイルを一度に選んでも構いません。

PDF、Word、Excel、PowerPointなど、配布したいファイルを追加できます。フォルダを開いてからアップロードすることで、選んだ分類に保存されます。ファイル名はサイトの資料名として使われます。

### 4. 変更をGitHubへ保存する

アップロード画面の下部にある **Commit changes** の欄を確認します。必要なら変更内容を短く記入し、保存先ブランチは通常 **main** のままにします。最後に緑色の **Commit changes** ボタンを押すと、追加したファイルがリポジトリに保存されます。

アップロード画面を閉じただけでは保存されません。必ず **Commit changes** まで完了してください。

### 5. サイトで確認する

GitHubへの保存後、GitHub Pagesの更新が終わるまで待ち、[公開サイト](https://nojitool.github.io/noji_tool_2.0/)を再読み込みします。資料名で検索するか、アップロード先と同じ分類タブを開いて表示を確認してください。反映されない場合は、次を確認してください。

- ファイルがリポジトリの正しい分類フォルダに入っているか
- アップロード後に **Commit changes** を押したか
- GitHub Pagesへの公開が完了しているか
- サイトを再読み込みしたか

ファイル一覧は公開リポジトリから取得します。リポジトリを非公開にした場合やGitHub APIで一覧を取得できない場合は、自動検出できません。その場合は公開設定を確認するか、後述の`files/catalog.json`を利用してください。

## 公開リポジトリのフォルダ構成

2026年11月8日に確認した公開リポジトリのルート構成です。資料は分類フォルダ直下へアップロードしてください。

```text
noji_tool_2.0/
├── index.html
├── logo.png
├── logo_login.png
├── all_logo.png
├── home_logo.png
├── av_logo.png
├── tech_logo.png
├── net_logo.png
├── 家電/
├── 季節AV/
├── 情報/
└── 通信/
```

資料を追加したあとの例です。

```text
情報/
├── SDカードマニュアル.pdf
├── Windowsマニュアル.pdf
└── プリンター選びガイド.xlsx
```

計画書どおりの`files/`構成を使う場合も、既存の分類フォルダを移動する必要はありません。`files/`の中に分類フォルダを用意した場合も、サイトは両方の配置を検出します。

### 資料名・更新日を指定したい場合（任意）

通常はファイル名がそのままサイトのタイトルになります。独自のタイトルや更新日を表示したいときは、リポジトリ内に`files/catalog.json`を作り、次の形式で登録できます。`path`は分類フォルダから見たファイル名です。

```json
[
  {
    "title": "エアコンの基本マニュアル",
    "category": "家電",
    "path": "エアコンの基本マニュアル.pdf",
    "updatedAt": "2026-11-06"
  }
]
```

`category`には`家電`、`季節AV`、`情報`、`通信`のいずれかを指定します。`readme.md`は一覧から除外されます。

## ロゴ画像と接続状態

カテゴリタブのロゴは`all_logo.png`、`home_logo.png`、`av_logo.png`、`tech_logo.png`、`net_logo.png`です。ヘッダーのカラー表示ロゴは`logo.png`、起動画面のロゴは`logo_login.png`です。同じファイル名で置き換えると差し替えできます。

ヘッダーの接続状態はFirebase Realtime Databaseとブラウザのネットワーク状態を表示します。初期読込や書込中は「連携中」と表示します。

## URLツールの登録

サイトの「URLを新規追加」から題名、URL、分類を入力します。登録・編集・削除はFirebase Realtime Databaseの`sharedTools`へ保存され、接続中の他端末にも反映されます。

## ローカルで確認する方法

`index.html`をファイルとして直接開くと、ブラウザの制約で一覧やプレビューが正しく動かない場合があります。プロジェクトのフォルダを開いてターミナルで次を実行し、表示されたアドレスをブラウザで開いてください。

```bash
python3 -m http.server 8000
```

通常は`http://localhost:8000`です。FirebaseのURL登録にはインターネット接続とRealtime DatabaseのRules設定が必要です。

## Firebase Rules

`rules.py`の中身はPythonコードではなく、Firebase ConsoleのRealtime Database Rulesタブへ貼り付けるJSONです。GitHubへ`rules.py`を置くだけではFirebaseの設定は変わりません。

このRulesは認証なしの公開読み書き設定です。サイトのURLを知らない第三者でも、データベースの読み書きができる状態になります。顧客情報・個人情報・認証情報・機密情報は登録しないでください。FirebaseのDatabase URLや公開APIキーだけではアクセス制御になりません。

## セキュリティと動作上の注意

- GitHub Pagesで公開したファイルは、URLを知る人が取得できる可能性があります。社内限定資料や機密資料はアップロードしないでください。
- Wi-FiのIPアドレスによるアクセス制限、パスワード認証は実装していません。
- QRコードはブラウザ内で生成します。長いURLでは短いサイト内リンク経由に切り替わる場合があり、その転送にはFirebaseの読み取りRulesが必要です。
- URL先がiframe表示を禁止している場合、プレビューに表示できないことがあります。その場合は「別タブで開く」を使ってください。
